# SubtitlesFinalizer

Workspace where a person and an AI assistant (Claude Code) put the **finishing touch** on `.srt` subtitle files that were produced by an automatic AI transcription / translation process of [FunscriptToolbox](https://github.com/Zalunda/FunscriptToolbox) (Japanese VR videos translated to English). The `*.final-ai-debug.srt` and `*.TERRAIN-MAP.srt` input files below are generated by FunscriptToolbox: better translation, lines split at real speech pauses, cues split or merged, questions asked to the person when only the video can tell.

This repo holds the **process and the tools**. The subtitle files themselves live in `Scenes/`, a separate private repo that is git-ignored here (and the videos are never in a repo).

* [AGENTS.md](AGENTS.md): how the assistant works here (rules, file conventions, tools). `CLAUDE.md` just includes it.
* [WORKFLOW.md](WORKFLOW.md): the step-by-step process (pilot, waves, final review, publishing).
* [STYLE-GUIDE.md](STYLE-GUIDE.md): translation and subtitle style rules.

## Requirements

* Python 3 (standard library only).
* `ffmpeg` on the PATH, only for `tools/extract_audio.py` (cut audio clips out of a video).
* Claude Code, to run the assistant side of the workflow (the tools also work by themselves).

## What you must provide in `Scenes/`

One folder per scene, one set of files per part (`A`, `B`, `C`...). The first two files come from the upstream AI process (they are inputs and are never modified):

```text
Scenes/
└── ABC-123/                                        scene folder (any name; it is the scene id)
    ├── ABC-123-A.final-ai-debug.srt                REQUIRED: subtitles + metadata (see below)
    ├── ABC-123-A.Worker.manual-input-preparer.TERRAIN-MAP.srt     OPTIONAL: where there is sound / silence
    ├── ABC-123-A.mp4                               OPTIONAL: the video (only for you; the assistant never reads it)
    ├── ABC-123-A.wipsubtitles                      REQUIRED: the toolbox project file; the assistant extracts the
                                                    .parts-duration.txt from it, then zips it as ABC-123.wipsubtitles.zip
    └── ABC-123.parts-duration.txt                  made by the assistant from the .wipsubtitles; needed only by
                                                    finalize_srt.py (end credits); only one per folder, one line per part:
                                                    ABC-123-A.mp4 00:29:40.970
```

The tools then create, in the same folder:

| File | Created by | What it is |
| :-- | :-- | :-- |
| `ABC-123-A.WIP.srt` | `create_working_srt.py` | the work in progress (the only subtitle file that gets edited) |
| `ABC-123-A.srt` | `finalize_srt.py` | the final file (CRLF, numbered, timings adjusted, credits injected) |
| `REVIEW.md` | the assistant | the single channel with you: doubts to check, questions with an `Answer:` line, suggested improvements, `## Scene name` |
| `GLOSSARY.md` | the assistant | scene glossary and character notes |

### Example of `*.final-ai-debug.srt`

A normal SRT where each cue has a `------- Metadatas -------` block. Each line is `[source] {Key:Value}` (a value can span several lines until the closing `}`). Made-up example:

```srt
1
00:00:05,317 --> 00:00:07,100
------- Metadatas -------
[manual-input] {OngoingContext:A nurse gives a sponge bath to a patient (POV). Tone: teasing, playful.}
[full-ai] {VoiceText:はい、お体を拭きますね}
[singlevad-ai-refined] {VoiceText:はい、お体を拭きますね。}
[singlevad-ai-refined] {TranslatedText:Okay, let me wipe you down.}
[singlevad-ai-refined] {TranslationAnalysis:Vector: talks to the patient (you). State: calm, Tier 1. Cadence: 1 part.}

2
00:00:12,094 --> 00:00:15,788
------- Metadatas -------
[full-ai] {VoiceText:退院、決まったんですって? おめでとう}
[singlevad-ai-refined] {VoiceText:退院、決まったんですって。おめでとう。}
[singlevad-ai-refined] {TranslatedText:Heard your discharge date's set. Congrats.}
```

* `[manual-input]` lines are the person's instructions: always obeyed. Any key starting with `Ongoing` (`OngoingContext`, `OngoingSpeakers`...) applies to every following cue until overridden, across all the parts of the scene.
* `[full-ai]` vs `[singlevad-ai-refined]` `VoiceText` disagreeing marks a suspicious transcription.

### Example of the optional `*.TERRAIN-MAP.srt`

Every cue is a piece of sound (`A`..`Z` cycling letters = voiced speech, `~` = breath / unvoiced); the gaps between cues are silence. `create_working_srt.py` merges it into the WIP as a `[terrain] {Silences:...}` line per cue, so the assistant knows where a subtitle can be cut:

```srt
1
00:00:05,300 --> 00:00:06,200
A

2
00:00:06,500 --> 00:00:07,100
B
```

Without a TERRAIN-MAP, no silence is assumed anywhere and any split of a cue goes through the person's ears.

## Quick start

```text
python tools/create_working_srt.py Scenes/ABC-123       # WIP files (never overwrites an existing one)
python tools/view_cues.py Scenes/ABC-123/ABC-123-A.WIP.srt --oneline    # read the cues
python tools/apply_cues.py Scenes/ABC-123/ABC-123-A.WIP.srt decisions.txt --dry-run
python tools/lint_srt.py Scenes/ABC-123/ABC-123-A.WIP.srt --min-severity warn
python tools/finalize_srt.py Scenes/ABC-123/ABC-123-A.WIP.srt            # the final .srt
python tools/publish_srt.py ABC-123 --release            # copy next to the videos (with BACKUPs) + Release/ folder
```

In practice you just tell the assistant "let's work on ABC-123"; it follows WORKFLOW.md and runs these tools. A decisions file for `apply_cues.py` looks like:

```text
@00:00:05,317                      # finalize: the cue keeps its timing, metadata removed, this is the text
Okay, let me wipe you down.

@00:00:12,094                      # split: each timing line starts a new cue
00:00:12,094 --> 00:00:14,245
Heard your discharge date's set.
00:00:14,690 --> 00:00:15,788
Congrats.

@00:00:40,112                      # question for the person (the cue keeps its metadata)
Q: Is she saying X or Y?
```

## Tools (`tools/`)

| Tool | Purpose |
| :-- | :-- |
| `create_working_srt.py` | create `<base>.WIP.srt` from the debug file + TERRAIN-MAP |
| `view_cues.py` | compact read-only view of the cues still to do |
| `apply_cues.py` | write the decisions (finalize, split, merge, question, delete, redo) into the WIP |
| `lint_srt.py` | style check driven by `lint.config.json` |
| `pair_cues.py` | English next to Japanese for every final cue (evidence for the final review) |
| `extract_audio.py` | cut the audio of cues out of the video (ffmpeg), for a second transcription |
| `finalize_srt.py` | produce the final `.srt` (timings, credits, numbering, CRLF) |
| `publish_srt.py` | copy the final `.srt` next to every copy of the video (with `BACKUP` files) and prepare `Release/` |
| `renumber_srt.py` | renumber an `.srt` |

Details of each tool are in [AGENTS.md](AGENTS.md), section 6.

## Configuration

| File | Content | Committed |
| :-- | :-- | :-- |
| `finalize.config.json` | minimum duration, extension, credit subtitles to inject | yes |
| `lint.config.json` | style rules and limits | yes |
| `extract_audio.config.json` | ffmpeg settings | yes |
| `publish.config.json` | release file names, forum links, backup tag | yes |
| `extract_audio.private.config.json` | `VideoFolders`: where your videos are (searched in order, recursively) | no (git-ignored) |
| `publish.private.config.json` | optional overrides of `publish.config.json` | no (git-ignored) |

`Release/` (files prepared for a forum post) and `Scenes/` are git-ignored in this repo.
